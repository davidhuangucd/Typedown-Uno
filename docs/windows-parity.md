# 与 Windows 原生版的功能差距

对照日期 2026-09-29。Windows 侧为 `flintt/Typedown` v1.2.30，Uno 侧为本仓库主线。这份清单以
**用户可见功能**为主，并记录会直接影响数据安全和发版质量的实现差异。

> 这份文件的上一版有两条是错的：它写着段落菜单缺五种图表、格式菜单缺加粗斜体等细项，实际上两者从 M3
> 起就齐全。教训是清单要对着代码逐条数，不能凭印象写。这一版的每一条都是照着两边的菜单定义数出来的。

## v1.2.30 同步基线

Uno 的编辑器资源已经从 Windows v1.2.27 更新到 v1.2.30，并保留 Uno 专用 `uno-bridge.js`。现已对齐：

- 阅读、源码和可视模式切换时保留原始 Markdown；
- 段落后直接出现 GFM 表格时仍能识别；
- Mermaid 错误不在正文底部残留，删除代码或切换标签后不重复堆积；
- HTML、SVG、公式和图表渲染的主动内容过滤；
- WebView 调用超时和监听器清理；
- 离线中英双语主题配色工具、已有主题目录和原生标签页状态配色。

可靠性也已按跨平台实现对齐：设置和会话串行原子写入、替换失败保留恢复副本、有损编码阻止自动保存、
刷新超时停止危险操作、多个未命名标签使用独立崩溃备份、HedgeDoc 密码进入系统安全存储。Uno 使用虚拟主机
映射承载编辑器，本来就没有 Windows 版曾使用的 `--disable-web-security` 参数，因此无需移植该项修改。

自动化基线包括编辑器单元测试、阅读/表格/Mermaid/安全浏览器测试、编辑器资源检查，以及不依赖 UI 的
原子写入、编码、设置顺序、主题目录注入、备份和会话测试。CI 先通过这些检查，才会构建三个系统的产物。

## 差距一：导出的可配置性

| | Windows | Uno |
|---|---|---|
| 导出格式 | HTML、PDF、图片 | HTML、PDF、图片 |
| 导出配置 | 每种格式可存多套命名配置：页边距、纸张、缩放、是否含大纲 | 固定：12mm 页边距、系统默认纸张 |
| 打印 | 打印对话框 + PDF 页面设置 | 系统打印对话框（WebKitGTK），无页面设置界面 |

Linux 上的 PDF 与图片导出走的是 WebKitGTK：文档渲染进一个离屏 WebKitGTK 视图，PDF 用它的打印操作直接
写文件，图片用它的整页快照写 PNG。配置界面没做，约 1~2 天。

## 差距二：图床上传

Windows 支持 OSS、Git、FTP、SCP、PowerShell 自定义脚本五种上传方式，各有配置页与多配置管理
（`UploadConfigModels`）。Uno 端没有任何一种。每种约 0.5~1 天。用户当前的优先级是「先不做」。

## 差距三：Windows 侧的打包

Uno 端目前只产出 zip；要在 Windows 上取代原生版，还需要 Inno 安装包、文件关联与「用 Typedown 打开」
右键菜单。约 1 天。

## 零碎

- 访问历史：Windows 存在 SQLite（`Storage.db`），Uno 存 JSON；功能等价
- 浮动 UI：Windows 用原生 XAML 浮层，Uno 由网页端绘制，风格略有差异
- 界面图标：Windows 用系统的 Segoe MDL2，Uno 用自带的 Fluent 图标字体，线条粗细与圆角有细微差别

## 接管 Windows 的前置条件

1. **实机验证 win-x64 产物**。2026-09-24 已在 Windows 上运行过 Uno 的 exe，中文输入正常；WebView2 承载、
   多窗口、文件关联仍待验证。PDF / 图片导出在 Windows 上走的不是 WebKitGTK，需要另一条实现（WebView2
   的 `PrintToPdfAsync` 与 `CapturePreviewAsync`），这是接管前必须补的一块。
2. **安装包**，见差距三。

最小接管集为差距一的配置界面、差距三的打包，以及 Windows 侧的 PDF / 图片导出实现，约 3~4 天；
加上图床再约 4 天。
